检查范围：

1. 使用工具当前源码的 `ReadPluginManifest` 逐个读取实际插件目录，全部返回有效的非 legacy 配置；必填字段、SemVer、目录 ID、入口路径及库文件由宿主校验。
2. 以两个仓库的 `.gitignore` 实际计算发布文件列表，核对入口、本地资源、库、文档链接和 SDK 副本；JavaScript 语法检查及 SVG 本地引用检查通过。没有未声明的外部库、外部资源请求或内部 RPC 调用。
3. 在真实浏览器中使用工具当前的 `sdk.js`、`plugin_host.js` 和插件实际模块，每个插件执行两轮激活／卸载。核对图层、样式表、场景与事件订阅、自建监听清理，并检查浏览器异常。
4. 工具本地 SDK 与插件宿主回归通过，覆盖两阶段接管、迟到异步回复、依赖激活顺序、失败清理及取消加载。这些测试文件保留在工具的本地工作区，不发布到插件仓库。

浏览器检查使用模拟的原生 RPC 和图标素材，验证插件与实际 JS SDK 的行为；本次没有启动真实桌面进行 Shell 图标、拖放或显示效果验收。原生层异常恢复和不同机器上的显示效果仍须用 Desktop Art 实测。

`particle-dissolve` 提供可选的 `window.desktopArtParticles` 诊断入口，并在卸载时删除；它内部仍调用公开 API，正常事件驱动播放不依赖宿主内部调试变量。

仓库中的 `$schema` 指向 `sdk/plugin.schema.json`，仅供编辑器使用。安装包不依赖该路径；需要安装目录内的编辑器提示时可改为 `../../host/plugin.schema.json`。
